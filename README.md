# zen-tab-grid

给 **Zen 浏览器**的左侧标签栏补上三项原生没有的能力：**多列网格**、**普通滚轮横向翻页**、**冻结标签变灰**。

面向 Zen 1.22.x / Windows。全部改动都是可逆的，不含任何联网上报。

## Zen 原生是什么样，我们加了什么

| | Zen 原生 | 装了本项目 |
| --- | --- | --- |
| 标签排布 | 单列，从上往下堆 | **多列网格**：先填满一列再开新列，行数随侧栏高度自动算 |
| 标签多了怎么办 | 只能上下滚 | 超出容量时**横向排列**，滚轮**直接左右翻页** |
| 滚轮手感 | 纵向滚（在标签栏上滚的是整条列表） | 一格滚轮 = 固定像素位移，**零动画、1:1 跟手**，可量化调节 |
| 被冻结（卸载出内存）的标签 | **外观和正常标签一模一样**，看不出来 | **明显变灰**，可选加 ❄ 标记 |
| 网格里的拖拽排序 | —（原生没有网格） | **拖到第几列就落在第几列**，落点指示线跟着走 |
| 文件夹（tab group）宽度 | 整条侧栏宽，和网格标签对不齐 | **与标签同一个公式**：几列就几列宽，还能两个并排 |
| 把散标签收进文件夹 | 手动拖，或 Zen 的智能分组（要先下载模型） | **右键一键整理**：按网站 / 本地相似度聚类，可撤销 |
| 安装方式 | — | 一个 bat，自动定位安装目录与配置目录 |

### 1. 多列网格

Zen 1.22 把标签放进了每个工作区自己的容器里，官方 CSS 针对的旧结构已经失效，所以网上流传的"userChrome.css 多列标签"方案在 1.22 上基本都不生效。本项目按实际运行时结构重写，并处理了两个 Zen 特有的坑（见下面"原理"）。

列数、行高、间距、行数全部可调；默认 `auto-fill` 让网格按侧栏高度自动铺满，**纵向不留空白**。

### 2. 普通滚轮 = 横向翻页

不需要按 Shift，也不需要触控板横扫：鼠标放在标签上滚，就是左右翻页。

这一项**必须靠一小段浏览器内 JS** 才能实现（原因见"原理"第 4 条），所以安装器会给 Zen 的 `omni.ja` 追加一个极小的加载器。不想改二进制就用 `-NoPatch` 安装，网格和变灰照常生效，只少这一项。

### 3. 冻结标签变灰

原生情况下，一个已经被卸载（不占内存）的标签和一个活跃标签长得完全一样，你无法判断点下去要不要重新加载。装好后：未加载的标签整体变灰，点回去立刻恢复。

**冻结这个动作本身**由 Firefox 完成（`tabs.discard()` → 销毁 `<browser>` 元素），触发方式有两种：Zen/Firefox 自己的自动冻结，或随本仓库附带的 **`extension/tab-butler-1.0.0.xpi`（标签页管家）** —— 它提供"超过 N 秒未使用就自动冻结 + 一键整理 + 关闭重复标签"，见下面《配套扩展》。本项目的贡献是让这件事**看得见**。


### 4. 网格里的拖拽排序

原生 Zen 的标签栏是一条竖线，所以它判断"要拖到谁旁边"的办法是：把指针的 Y 坐标和标签们的 Y 坐标做一次区间二分。放进两列网格后，Y 不再随标签序号单调递增（第二列的 Y 会和第一列重复），二分只能落在第一列 —— 表现就是"标签只能拖到第一列"。

本项目不重写拖拽，只把 Zen 自己留的口子接上：它在 dragover 时优先采用**命中的那个元素**（`event.target.closest(".zen-drop-target")`），前后半区由指针在该标签内的纵向位置决定 —— 列优先网格正好就是这个轴。于是 `userChrome.js` 给网格里的普通标签补上这个类，落点和那条横向指示线就自动变成二维的。实测：指针停在第二列的 20 / 22 / 24 号标签上，落点分别是 20 / 22 / 24，指示线 x=256.5px；补类之前落点全都被拽回 0 / 1 / 3。

固定标签、白名单里的 essentials、以及**已经进了文件夹的标签**不加这个类，仍走原生判定 —— 拖进文件夹的语义完全没动。文件/链接拖入、拖出成新窗口、跨工作区拖拽也一律保持原生。

顺带修掉一个同源的外观问题：「新建标签页」按钮原本是标签区的子元素，在网格里会白占第一列的第 0 格，把第二列整列顶得比第一列高一格。现在它被提出来铺满顶部一条，两列顶端对齐（实测两列首标签同为 y=147）。

### 5. 文件夹与标签同宽

Zen 的文件夹（`<zen-folder>`）其实是**固定标签容器**的子元素 —— `gZenFolders.createFolder()` 会把进文件夹的标签逐个 `pinTab()`，所以文件夹原生被撑成整条侧栏宽（实测 495px），而下面的网格标签只有 245px：上面一条横的、下面两列的，怎么都对不齐。

改法不是搬 DOM（那会牵动文件夹展开动画、拖进文件夹、会话恢复一整套逻辑），而是把文件夹的宽度换成**和标签完全同一个公式** `calc((100% - (columns-1)*gap)/columns)`：`--uc-grid-columns` 设成几，文件夹就是几列宽。容器再开 `row wrap`，两个文件夹就能并排占掉两列；零散固定标签强制 `width:100%`，仍然一行一个。实测：标签 246px，grpA 246px @x=5、grpB 246px @x=251 并排，固定标签 495px 独占一行。


### 6. 一键整理成文件夹（入口：标签右键菜单）

在任意标签上**右键**，最下面多了三项：

| 菜单项 | 做什么 |
| --- | --- |
| 🗂 按网站整理成文件夹 | 同一个网站（eTLD+1）有 ≥2 个标签就收进一个文件夹，文件夹名就是域名。确定性、永远能用 |
| ✨ AI 整理（本地相似度） | 读所有标签的**标题 + 网站**（已经在文件夹里的也读，会先解组再按新规则重排），分词后做相似度聚类，文件夹名取簇内最有区分度的词。全程本地计算，不联网 |
| ↩️ 撤销这次整理 | 打散上一步建出来的文件夹，标签回到普通序列 |

两个整理动作都建在**原生标签组**（`gBrowser.addTabGroup()`）上，所以文件夹落在标签区里、跟着网格走，而不是跑到顶部那条固定标签栏。

**为什么不用 Zen 自带的 SmartTabGrouping**：它确实在这份构建里（`moz-src:///browser/components/tabbrowser/SmartTabGrouping.sys.mjs`，`browser.tabs.groups.smart.enabled` 也是 true），但它走 `embeddingsGeneratorFactory.forGeneral()` —— 要先从 HuggingFace 下载嵌入模型，国内基本连不上，失败时表现就是按钮一直转圈。所以这里用本地分词 + 完全链接聚类顶替；哪天模型能下下来，可以把它接成第三个入口。

实测（12 个标签、3 个网站的干净样本）：按网站 → 3 个文件夹（4/4/2 个成员，`grid-row: span` 分别为 4/4/2），12 个标签位置互不重叠；AI 整理 → 同样 3 个文件夹，名字是 `tempmail` / `movies` / `news`；撤销 → 文件夹数归 0，无残留空壳；连点两次不会翻倍。

两个坑记在这里：**`tab-group.ungroupTabs()` 在这个 Zen 里是空操作**（它遍历 `tabsAndSplitViews`，实测长度为 0，而 `g.tabs` 有 12 个），必须逐标签 `gBrowser.ungroupTab(t)`；**聚类不能用单链接**（并查集会把 A-B、B-C 传递成一坨，实测 12 个标签并成 1 个文件夹），所以改成完全链接，并丢掉出现在六成以上标签里的无区分度词。


## 安装

**下载 `zen-tab-grid.exe`，双击运行，选 1。** 它会自动定位 Zen 安装目录和你真正在用的配置目录 → 装好 CSS/JS → 需要写 `Program Files` 时自己弹 UAC 提权 → 备份 `omni.ja` 后再打补丁。全程不用填路径、不用解压、不用装任何依赖。

然后**完全退出 Zen（菜单 → 退出）再打开**即生效。

| 菜单项 | 作用 |
| --- | --- |
| 1 完整安装 | 三项功能全开（会请求管理员权限） |
| 2 仅装样式 | 免管理员；有网格 + 冻结变灰，滚轮仍是上下滚 |
| 3 检查并更新 | 从仓库拉最新 CSS/JS 重装，并自检补丁是否被 Zen 更新冲掉 |
| 4 卸载补丁 | 还原 `omni.ja.bak` |

命令行也能用：`zen-tab-grid.exe --install | --style-only | --update | --uninstall | --status`

**SmartScreen 拦你怎么办**（未签名 exe 的常见情况）：点弹窗里的「更多信息」→「仍要运行」。不想用 exe 的话，仓库里的 `install.bat`（右键 → 以管理员身份运行）效果完全一样；exe 的源码就在 `src\Program.cs`，想自己编译跑 `src\build.cmd` 即可（只用 Windows 自带的 csc.exe，无第三方依赖）。

> Zen 会在 `profiles.ini` 里留一个带 `Default=1` 的空壳配置目录，按"默认标记"找会装错地方 —— 安装器改用 `[Install<hash>]` 里的真实路径，并以 `prefs.js` 的写入时间兜底。


## 配置

改 `<配置目录>\chrome\userChrome.css` 顶部，重启 Zen 生效：

```css
:root {
  --uc-grid-rows: auto-fill;  /* 一列几行。auto-fill=按侧栏高度自动铺满；也可写数字如 8 */
  --uc-grid-columns: 2;       /* 每排几列 */
  --uc-tab-h: 36px;           /* 单个标签高度 */
  --uc-grid-gap: 4px;         /* 标签间距 */
}
```

改滚轮步长：`<配置目录>\chrome\userChrome.js`

```js
const PX_PER_LINE = 16;   // 一格滚轮 ≈ 48px；调小更细腻，调大更快
```

改变灰程度 / 加 ❄：`userChrome.css` 末尾的 `opacity` 数字，以及那段注释掉的 `::after`。

## 配套扩展：标签页管家（真正执行冻结的那个）

`extension/tab-butler-1.0.0.xpi`，源码就在同目录（`manifest.json` / `background.js` / `popup.*` / `options.*`）。功能：

- **自动冻结**：超过设定秒数（默认 60）未使用的标签被 `tabs.discard()` 卸载出内存，标签留在栏上，点回去自动重新加载
- **一键整理**：每个窗口内固定标签排最前，其余按 域名 → 标题 → 网址 排序
- **关闭重复标签**：同网址只保留最近使用的一个
- 豁免规则可配：固定标签、正在出声的标签、白名单域名

**安装**（Zen 这个构建 `MOZ_REQUIRE_SIGNING=false`，未签名扩展可以直接装，不用改任何配置）：

1. 地址栏输入 `about:addons` 回车
2. 右上角菜单（≡）→ **从文件安装附加组件…**
3. 选中 `extension/tab-butler-1.0.0.xpi`

设置项在扩展的「选项」里，或点工具栏图标开弹窗（可手动"立即冻结"、看统计）。

**为什么要和上面的 CSS/JS 配套用**：扩展能执行冻结，但**给不了标签任何视觉标记** —— 扩展进不了 `browser.xhtml` 这个浏览器 UI 文档，而 Firefox 又只在强制卸载时才打 `discarded` 属性。所以"冻结"靠扩展、"看得见"靠本项目，缺一个都不完整。

## 更新与卸载

- **更新**：双击 exe 选 3（或右键 `update.bat`）。从本仓库拉最新文件并重装 CSS/JS；同时会自检 `omni.ja` 补丁是否还在（Zen 自动更新会把它冲掉），缺失时提示你重装补丁。
- **卸载**：双击 exe 选 4（或右键 `uninstall.bat` → 管理员运行），还原安装前的 `omni.ja` 备份。要彻底回到原状，再删掉配置目录下的 `chrome\userChrome.css`、`chrome\userChrome.js`，以及 `user.js` 里本项目追加的那两行。

## 原理（为什么原生 CSS 做不到这些）

1. **Zen 1.22 把工作区标签搬走了。** 标签的实际父级是 `zen-workspace` 内部的 `.zen-workspace-normal-tabs-section`，不再是官方 CSS 针对的 `#tabbrowser-arrowscrollbox`。
2. **userChrome.css 不能用 `::part()` 穿透 shadow DOM**（Firefox 禁止用户级样式表穿透），所以任何要改 arrowscrollbox 内部滚动的方案都不可行。本项目全部基于 light DOM。
3. **空网格也会占位。** `grid-template-rows: repeat(8, 36px)` 的 8 条显式轨道即使格子里没内容也会实体化高度。所以固定标签区不做网格化，普通标签区加 `:has(> .tabbrowser-tab)` 守卫 —— 否则顶部会凭空出现一大片空白。
4. **普通滚轮无法用 CSS 变成横向。** 浏览器按物理方向派发滚轮增量，纵向增量只会去找纵向可滚容器；而 Zen 的模组系统是纯 CSS（`ZenMods.mjs` 只有 Stylesheet service），扩展也进不了 `browser.xhtml`。所以用 `omni.ja` 里的加载器 + `loadSubScript` 读配置目录的 JS，把滚轮增量直接写成 `scrollLeft +=`（不经任何动画，所以跟手）。
5. **冻结标签原本没有任何可样式化的标记。** Firefox 只在**强制**卸载时才打 `discarded` 属性（`if (aForceDiscard) tab.toggleAttribute("discarded", true)`），而扩展 API `tabs.discard()` 走的是不传 force 的路径 —— 冻结确实成功了（`<browser>` 元素被销毁、内存释放），但标签上不留痕迹。本项目自己识别"browser 未连上文档"的标签并打 `tb-frozen`。
6. **拖拽落点是一维算出来的。** `drag-and-drop.js` 的 `_getDropIndex()` 只看 `screenY`，而真正决定落点的 `dropElement` 来自 `_animateTabMove()` 里对 `ariaFocusableItems`（按 DOM 顺序排列）做的 Y 轴二分 —— 这套算法的前提是"标签条是一条线，Y 随序号单调"。两列网格里第二列的 Y 会和第一列重复，二分必然回到第一列。Zen 在这条路上留了个 DOM 命中的优先分支（`.zen-drop-target`），本项目只是把网格里的标签接进这个分支，没有替换任何拖拽代码。

## 已知限制

- **Zen 自动更新会覆盖 `omni.ja`**，表现为"滚轮又变成上下滚"。重跑 `install.bat` 即可（幂等，只补那一处，不会把 omni.ja 的其它内容回退）。
- 会话恢复后还没点开过的标签也会显示为灰 —— 它们本来就不在内存里，属正常。
- 只在 Windows 上测试过（Zen 1.22.3b / Win11）；macOS/Linux 的路径定位需要另写。
